## P0 阻塞

### 1. Release RPK 的签名合同仍被留给项目 Spec

[Runtime Artifact Contract](../../spec/contracts/artifact-contract.md) 要求 release 包验证签名，却又把签名算法、证书链和相关细节留给 Toolkit/Core 项目 Spec。Toolkit 是签名生产方，Core 是验证方；两者在总架构通过后并行写 Spec，不能分别决定同一个签名协议。

当前 [Runtime Metadata Schema](../../spec/contracts/schemas/runtime-metadata.schema.json) 还允许包内自行声明 `signaturePolicy=development|release`。如果 Runtime Host 没有包外可信策略，未签名包可以把自身声明为 development，从而形成降级路径。

总合同必须至少冻结：

- 固定签名成员路径和机器格式；
- 精确的被签名内容、顺序或 canonicalization 规则；
- V1 算法、证书/公钥表示及信任来源；
- 重复 ZIP member、Manifest、Runtime Metadata 和 Artifact Descriptor 如何纳入签名；
- development 是否允许无签名必须由包外可信 `PackageOpenPolicy` 决定，包内字段不得自行降低验证级别；
- Toolkit 生成结果与 Core 验证结果的 Golden/反例。

ZIP 大小上限可以由 Core 实现 Spec 细化，但签名生产/消费格式必须留在公共合同。

### 2. Root Surface 的首次展示链路没有闭环

[Platform Surface Contract](../../spec/contracts/platform-surface-contract.md) 定义了 `PresentSurfaceHost(mode=root)`，但只为 push 写出了完整生命周期。[Surface Control](../../spec/contracts/surface-control.md) 的 root 创建链路在 `CreateSurfaceHostResult` 后交付 `SurfaceContext`，首屏流程在 full Mount 和 `InstantiateTemplateResult` 结束，没有调用 root Present。

因此不同 Agent 仍会作出不同实现：

- full Mount 后 Core 自动 Present，还是 Runtime Host 再发命令；
- `InstantiateTemplateResult(instantiated)` 在 mounted 后还是 presented 后返回；
- root Present 失败时返回哪个上层 Result、Surface 进入 failed 还是 hidden-mounted；
- visible root 能否直接 Destroy；
- push Present 成功后 source/target 的 Platform Surface 状态如何原子变化。

必须补一条唯一 root 状态机：`CreateHost -> full Mount hidden -> Present root -> 上层成功`，并冻结 Present 失败、销毁和结果顺序。否则 Android、LVGL、iOS 的首屏完成语义不同。

## P1 问题

### 1. Page IR 的“树”约束和语义测试不完整

[Artifact Contract](../../spec/contracts/artifact-contract.md) 要求静态根不属于 Block、Block 不递归；但 [Page IR Schema](../../spec/contracts/schemas/page-ir.schema.json) 只能校验局部字段。当前 [测试器](../../spec/contracts/schemas/tests/validate-schemas.mjs) 的 `validatePageIrSemantics` 只检查 ID 唯一和引用存在，没有检查：

- root 入度为 0，其他节点只能有一个结构父级；
- 节点/Block 图无环、Block root 不回指祖先；
- Block root 和静态树不能共享同一节点；
- Block parent、node child slot 和 template root 三者关系一致；
- 每个 Binding/Handler 的目标属于正确静态或 Block 模板范围。

这些约束决定 Core 如何从 Page IR 创建唯一 Runtime Tree，必须写成明确公共不变量，并添加环、多父、共享 root 和错误归属反例。

### 2. Artifact 关系测试尚未覆盖合同宣称的全部关系

当前关系测试已覆盖 packageId、entryRoute、page route/component、page bootstrap 和部分唯一性，但仍未覆盖：

- Manifest 普通 pages 与 Runtime Metadata pages 的双向一一对应；
- app/shared/page 的 `moduleId` 全局唯一；
- page dependencies 必须指向已声明且允许的 module；
- app bootstrap 与 Metadata app module 的对应关系；
- Contract 所述 templateId 和全部 Artifact Descriptor 的命名空间唯一性；
- release/development 策略和签名 Artifact 的关系。

因此 `Validated 16 schemas, 55 union branches, and Artifact relationships.` 命令本身通过，但还不能证明全部 Artifact 关系通过。应补齐关系校验和逐项负例，再更新基线声明。

## 已关闭项

1. `MoveBlock -> MoveHost` 已冻结唯一映射、最终 index、跨父移动、递归 RemoveHost 和 full Mount 限制。
2. HandlerId 已冻结为 Surface 内唯一且不复用的绑定级身份。
3. Toolkit v2 研究路径已经可从 Handoff 正确解析。
4. 16 份 Schema 均通过 Draft 2020-12 strict 编译，55 个顶层联合消息分支均有正例和未知字段反例。
5. v3 基线、项目目录、Handoff、代码边界和严格门禁保持正确，没有提前启动项目 Spec 或编码。

1. 将 release 签名生产/验证和可信 PackageOpenPolicy 冻结为公共合同与自动 Golden。
2. 补齐 root Surface 从隐藏 full Mount 到首次 Present 的唯一状态机和结果顺序。
3. 明确 Page IR 图不变量，并添加完整语义校验及反例。
4. 补齐 Manifest/Metadata/Page IR/Bootstrap 的双向关系、全局唯一性和依赖校验。
5. 重新执行全部 Schema、分支和 Artifact 关系测试。
