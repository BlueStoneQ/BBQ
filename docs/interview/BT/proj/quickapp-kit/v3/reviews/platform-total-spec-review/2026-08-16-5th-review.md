### 2.1 P1-001：必选 JS Framework 的 Manifest 与链接证据

**结果：通过，原 P1-001 已闭环。**

已验证事实：

1. `spec/contracts/runtime-composition-contract.md:15-19,25-30` 继续区分固定 C++ Kernel、必选 JS Runtime Service 和可替换 Engine Provider；JS Framework 没有被并入 C++ Kernel。
2. 同合同 `:37-49,65-76` 冻结 Composition Root 的组成过程，并要求六个 Kernel module 与 `runtime.js-framework(category=runtime)` 始终且各自只出现一次；Engine module 必须且只能有一个，并与 `jsEngine.moduleId` 一致。
3. 同合同 `:110-121` 要求 Manifest 中的 `runtime.js-framework` 与 link map/symbol inventory 对应；仅声明但未实际链接时构建失败。
4. `spec/contracts/schemas/runtime-composition.schema.json:27-50` 将 `linkedModules.minItems` 提升为 8，并用 `contains + minContains=1 + maxContains=1` 强制 `runtime.js-framework(category=runtime)` 恰好一次。
5. `spec/contracts/schemas/tests/fixtures.mjs:445-470` 的公共正例已包含 `runtime.js-framework(category=runtime)`、一个 QuickJS Engine module 和目标 Platform module。
6. `spec/contracts/schemas/tests/validate-schemas.mjs:90-100` 同时执行 moduleId 唯一、单 Engine 且 moduleId 匹配、JS Framework 恰好一次的跨字段语义校验。
7. `spec/contracts/schemas/tests/fixtures.mjs:619-655` 直接覆盖 JS Framework 缺失、错误 category 和重复三种负例。
8. LVGL、Android、iOS 验收分别在 `projects/quickapp-runtime-lvgl/spec/acceptance.md:16-24`、`projects/quickapp-runtime-android/spec/acceptance.md:16-25`、`projects/quickapp-runtime-ios/spec/acceptance.md:16-25` 要求 Manifest 与 link map 或 symbol inventory 对应证明一次 JS Framework 和唯一 Engine。

额外 Ajv 探针真实结果：

```text

```

结论：Manifest、Schema、正例、语义校验和三个平台验收使用同一 `runtime.js-framework(category=runtime)` 事实；文字声明与实际链接证据已经闭合。

### 2.2 P1-002：External Function 归属

**结果：通过，原 P1-002 已闭环。**

已验证事实：

1. `projects/quickapp-runtime-js/spec/requirements.md:20-35` 已把通用链路写为 `JS Framework + selected Engine Provider`，Framework 输入是 `JsEnginePort` Native Function Binding 的同步 `EnqueueResult`，并明确 QuickJS External Function 不属于 Framework 输入。
2. 同文件 `:64-67` 继续规定 Runtime ABI 使用 Engine 无关 Native Function Binding；QuickJS Provider 只负责把它映射为 External Function。
3. `projects/quickapp-runtime-js/spec/subspec-index.md:17-21` 将 QuickJS Provider 及其 External Function Adapter 唯一分配给 JS-S01；JS-S02 只负责基于 `JsEnginePort` Native Function Binding 的 typed codec、`EnqueueResult` 和 request/result 关联。
4. `spec/contracts/capability-module-contract.md:91-102` 已将公共边界冻结为 `JsEnginePort Native Function Binding + 封闭 typed union`；External Function 仅作为 QuickJS Provider 的实现方式，其他 Provider 使用各自 native binding 映射到相同 typed ABI。
5. `spec/contracts/runtime-abi.md:12-15` 仍明确 Runtime ABI 是 JS Framework 与 Core 的唯一调用边界，External Function 只是 QuickJS 绑定方式。
6. 对 `spec/`、`projects/`、工作看板和启动文档执行残留扫描，没有发现把 External Function 分配给 JS-S02、通用 Runtime ABI Client 或 JS Framework 的有效表述。现有命中均明确限定为 QuickJS Provider，或明确禁止把 Host lifecycle 伪装为 External Function。

结论：JS-S01 与 JS-S02 不再双重拥有 binding 入口；公共 Bridge 保持一条 Engine 无关 Native Function Binding + typed Runtime ABI。
