**结论：先做 5 个指标域，每域只保留最能证明框架价值的 3 个指标。**

| 指标域 | Top 3 指标 | 反映什么 | 怎么测 |
|---|---|---|---|
| 启动 | `TTFF` 首帧时间 | 用户多久看到完整页面 | `launch → first present` |
|  | Runtime 初始化时间 | QuickJS、libuv、Core 的启动成本 | `runtime start → ready` |
|  | RPK 加载时间 | 读取、校验、解析效率 | `open → package verified` |
| 更新 | State-to-Present | 状态变化到屏幕更新的总延迟 | `state write → present` |
|  | Core 事务时间 | Tree 更新、布局、生成指令的效率 | `intent received → mount posted` |
|  | 增量指令数 | 是否真正做到定点更新 | 统计单事务 Mount 指令数 |
| 交互 | Input-to-Handler | 输入传到 JS 的响应速度 | `platform input → handler start` |
|  | Input-to-Present | 点击到最终画面变化 | `platform input → present` |
|  | 丢帧率 | 交互是否流畅 | 超帧预算帧数 / 总帧数 |
| 资源 | 稳态内存 | Runtime 常驻成本 | 页面空闲稳定后采样 |
|  | 峰值内存 | 首帧或复杂更新的内存压力 | 记录 RSS/平台高水位 |
|  | CPU 时间 | 启动或更新的计算成本 | 统计线程 CPU time |
| 稳定性 | 页面销毁残留 | 是否泄漏 | 多轮进出后的内存净增长 |
|  | 事务失败率 | 主链路可靠性 | 失败事务 / 总事务 |
|  | P99 延迟 | 极端情况下是否稳定 | 多轮采样统计 P99 |

**最优先 Top 5：**

```text
1. TTFF
2. State-to-Present
3. Input-to-Present
4. 稳态/峰值内存
5. 页面销毁残留
```

这五个指标分别证明：**启动快、更新快、交互快、资源省、生命周期可靠。**
