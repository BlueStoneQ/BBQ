# Vela QuickApp 调试系统

## 结构：前端在 IDE，后端在框架
- 前端：VSCode 插件，内嵌 Chrome DevTools（复用现成调试 UI）。
- 协议：CDP（调试语义）跑在 WS（传输通道）上。
- 后端：框架内的调试后端 + WS 通信端。
- 通道形态：一个统一的 WS 出口对接 IDE；后端按 CDP 域分发/汇聚，各域消息汇到这一个 WS 收发。

## 本质：QuickJS 无现成 inspector，全域自实现
hap 用 V8，JS 域调试可白嫖 V8 自带 inspector；Vela 用 QuickJS，没有这套现成能力，
DevTools 全套主力域从零自实现：DOM / Console / Network / Debugger(断点) / Memory。
业界无现成的 QuickJS CDP 实现——这是自研，对应 CDP 40+ 组协议。

## 断点方案（务实、不侵入引擎）
- setBreakpoint：DevTools 点某行 → 前端发 setBreakpoint CDP → 后端在源码对应行注入 `debugger` 标志。
- 命中：点运行后 JS 顺序执行，执行到 `debugger` 触发回调停下。
- 停下：发 `Debugger.paused` CDP，带上当前作用域变量给面板。
- 继续：前端点 next/继续发 CDP，后端放行，顺序执行到下一个 `debugger`。
- 巧劲：借 JS 原生 `debugger` 语句 + 顺序执行特性，把断点降维成"跑之前在源码里插一句话"，
  不碰引擎字节码、不改引擎源码，用引擎暴露的钩子在其外搭一层调试器。
- 调用栈：QuickJS 可遍历调用帧取快照拼成 CDP callFrames，能做，按优先级取舍。

## 价值
稀缺(QuickJS 上从零自研 CDP，业界无现成) + 完整(DevTools 全域打通) + 干净边界(引擎当黑盒、调试器是其上一层，不侵入)。
