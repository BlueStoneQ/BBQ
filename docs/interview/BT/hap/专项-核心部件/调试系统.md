## 总述
前端是基于vscode的IDE的插件，里面其实是chrome的devtools
调试协议是cdp，通信协议是 ws
后端在框架里面：包括调试业务后端 + ws通信端
## 调试后端
- hap 的调试后端是"两半"，别当成一件事：

- JS 引擎调试（断点/栈/console/内存） → V8 自带 inspector 出 CDP。hap 不实现这套协议，只做"把 V8 inspector 接到 WS 通道上"。—— 这半是你说的"V8 已实现"。

- UI/Elements 调试（看 DOM 树、节点样式、命中元素） → hap 自己实现。因为 hap 渲染的是 Native View 树（VDocument/Component），不是浏览器 DOM，V8 inspector 根本不知道这棵树。所以 onAppliedChangeAction、InspectorVElementType、setRootView 这些都是 hap 自己把 Native 渲染树翻译成 CDP 的 DOM 域协议喂给 DevTools，让 Elements 面板能显示。—— 这半是 hap 自己造的。
 
- 所以 hap 调试后端的本质：
    - JS 域：白嫖 V8 inspector（省了实现 Debugger/Runtime/Console 这些 CDP 域）。
    - DOM/CSS 域：自己实现（因为渲染树是 Native 的，得自己翻译成 CDP DOM 协议）。
    - WS：getWebSocketFactory() 提供通道，把上面两半的 CDP 消息收发出去。

## 实现细节
- V8 不自己起 WS server；V8 inspector 和自实现的 CDP 汇到同一个外部出口，走统一的一个ws server
```
IDE(DevTools) ──CDP over WS──► [框架里的 WS 通信端(唯一网络出口)]
                                        │  按 CDP 域分发
                        ┌───────────────┴───────────────┐
                   JS 域(Debugger/Runtime/Console)   DOM/CSS 域
                        │                                │
              V8 inspector（进程内 Connection）    hap 自实现（Native 树翻译）

```
- 协议分发器（基于CDP域配置）:框架的 WS 端做分发/汇聚：从 IDE 来的 CDP 消息，按方法域路由——JS 域(Debugger./Runtime.)转给 V8 的 Connection，DOM/CSS 域交给 hap 自实现的处理；反向，两边产出的 CDP 消息都汇到这一个 WS 发回 IDE。
