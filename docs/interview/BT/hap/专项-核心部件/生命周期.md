生命周期本质你说的对——就是"预注册 hooks、到点触发"的过程，每个页面/App VM 上挂着自己声明的这些 on* 方法，框架在对应时机 _emit 触发。

hap 生命周期钩子，按类分：

核心生命线（VM 的"一生"，最主力）：

onCreate —— VM 创建（xlc:onCreate 内部触发）
onInit —— 初始化（响应式化后）
onReady —— 页面首次渲染完成、可交互
onShow —— 页面显示（含 back 复现时）
onHide —— 页面隐藏（跳走时）
onDestroy —— VM 销毁（真正离开时）
交互/系统事件类：

onBackPress —— 返回键
onMenuPress / onMenuButtonPress —— 菜单键
onKey —— 按键
onPageScroll / onReachTop / onReachBottom —— 滚动相关
onRefresh —— 下拉刷新（1050+ 版本新增）
onConfigurationChanged / onOrientationChange —— 配置/横竖屏变化
错误/异常类：

onError / onErrorHandler / onErrorCaptured（1300+ 新增）—— 错误捕获
onPageNotFound —— 路由找不到页
要点（对应你说的"简单模型"）：

本质是 hooks 表：VM 上按名存着这些 on* 方法（就是 XVm 构造时从 options 拆出来的那批），到点 _emit(name) 触发——触发 = 查这个 VM 有没有这个 hook，有就调。
两类要分：onCreate/onInit/onReady/onShow/onHide/onDestroy 是核心生命线（VM 生死显隐）；其余是事件回调（用户操作/系统变化），不是严格的"生命周期"，但也走同一套 hook 机制。

- Native为源头触发的lifeCycle：
    - 路由变化 → PageManager 改 List<Page> 栈
    → 通知 RootView.onPagePreChange / onPageChanged（主线程）
    → RootView 摘挂 View 树（detach 旧页 / attach 新页 cacheDoc）
    → 通过 JsThread 跨线程通知 JS（postExecuteFunction → 在 JS 线程执行）
    → JS 侧对应 Page 的 vm._emit('xlc:onHide')（旧页）/ _emit('xlc:onShow')（新页）
    → emit 查监听表 → 执行用户的 onHide/onShow
        onDestroy：页面真正 back 销毁时，misc.js:132 vm._emit('xlc:onDestroy')
