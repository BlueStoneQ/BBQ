## 本质

**考的不是"你会不会写代码"，是"你能不能驾驭 AI 做出超预期的东西,还有利用AI去做好不属于自己之前领域的东西"。** 把自己当项目经理/架构师，AI 是你的 junior 团队。过程权重 > 结果权重。

---

## 大纲（3 条）

1. **凌驾 AI，不被牵着走**：每一步都要质疑 + 纠偏 + 补充，体现你的判断力（这是第一得分点）
2. **拆解到原子级 + 分角色执行**：大任务拆成小任务，每个任务给 AI 一个专业角色，不要一次性甩所有需求
3. **边做边交付，不要最后才输出**：每完成一个阶段就生成文档/文件，避免超时白交

## 总览

| 阶段 | 时间占比 | 做什么 | SSP 加分行为 |
|------|---------|--------|-------------|
| **理解 + 拆解** | 15% | 读题 → 拆目标 → 定验收标准 → 规划时间 | 主动定义"题目没说但应该做"的事 |
| **方案设计** | 20% | 让 AI 出方案 → 多方案对比(TOP3方案=>1方案, 第一性原理+本质+学会选型) → 你做决策 | 质疑 AI 方案漏洞，给出更优思路 |
| **执行实现** | 50% | 分角色 prompt → AI 生成 → 你 review → 纠错迭代 | 多窗口并行、分步验证、及时 commit |
| **复核提交** | 15% | 检查交付物 → 统一格式 → 压缩提交 | 让 AI 扮演"严格检查者"做最终审核 |

## 关键操作

### 开局（前 10 分钟）

```
1. 读完题目，在脑中（或 md 文件）列出：
   - 核心目标是什么
   - 交付物有哪几个（方案文档 + HTML demo + 数据看板）
   - 时间怎么分配

2. 先建好文件夹结构：
   /project
   ├── docs/          ← 方案文档
   ├── src/           ← 代码
   └── output/        ← 最终交付物

3. 告诉 AI：所有输出都存到这个路径下
```

### 分角色 prompt（核心）

```
第一轮：需求分析师
"你是资深产品经理，帮我拆解这个任务的核心需求，列出优先级和验收标准。"

第二轮：架构师
"你是技术架构师，给出 2-3 个方案，对比 trade-off，推荐一个并说明理由。"

第三轮：开发者
"你是全栈开发工程师，按方案 X 实现。技术栈：HTML + Tailwind + Chart.js。"

第四轮：检查者
"你是极其严格的代码审查员，检查上面的实现有没有 bug、遗漏、可优化的地方。"
```

### 质疑（得分关键）

每 3-5 轮对话必须有一次显式质疑：
- "你这个方案没有考虑 XX 场景，补充一下"
- "为什么选 A 不选 B？给我理由"
- "这段代码有性能问题，用 XX 方式重写"
- "你的数据分析缺少 XX 维度，补上"

### 避坑

| 坑 | 后果 | 解法 |
|----|------|------|
| 一次性甩所有需求 | AI 输出又长又乱 | 一次一个小任务 |
| 不切模型 | 默认模型可能是 qwen 很慢 | `/model` 切 opus |
| 最后才输出文件 | 超时没提交 | 边做边存，每阶段 commit |
| 只在一个窗口 | 上下文撑爆变慢 | 多开窗口，阶段性新开 |
| 不知道压缩包在哪 | 最后 3 分钟找不到文件 | 开始就确认提交路径 |

### 对话轮数

建议 **≥ 30 轮**。不要 5 轮就结束了——轮数少说明你没有深度交互、没有质疑、没有迭代。

### 多 Agent 协作（多窗口模拟）

Claude Code 没有内置 agent teams 机制。用**多终端窗口 + 文件系统通信**手动模拟：

```
你（Leader）= 主窗口，做决策 + 分派任务 + 汇总验收

窗口 A（分析师）→ 输出 docs/analysis.md
窗口 B（开发者）→ 读 analysis.md → 输出 src/ 代码
窗口 C（检查者）→ 读 src/ → 输出 docs/review.md
你在主窗口 → 读 review.md → 决策下一步
```

本质 = 文件系统当消息队列。每个窗口是一个独立上下文的"员工"，写文档汇报给你（leader），你读完做决策再分派。避免单窗口上下文撑爆变慢。

**注意**：多窗口不要关闭，关了可能丢记录。用 `/resume` 可在新窗口恢复之前阶段。
