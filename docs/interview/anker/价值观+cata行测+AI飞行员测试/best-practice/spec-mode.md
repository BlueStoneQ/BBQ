# Spec 模式认知体系建设

> 本质：需求 → 设计 → 任务 → 实现 → 验证，每一步有明确产出物。

---

## 大纲（3 条）

1. **先定义"做什么"再动手**：需求文档 → 验收标准 → 才开始写代码
2. **每一步有交付物**：不是聊完就开始写，而是 spec → design → task list → code → test
3. **验收驱动**：先定义"做成什么样算完"，再反推实现路径

---

## 速查表

| 阶段 | 产出物 | 在飞行员测试中 |
|------|--------|--------------|
| Requirements | 需求文档（核心功能 + 优先级 + 验收标准） | 开局 10min 输出 requirements.md |
| Design | 技术方案（架构图 + 选型 + trade-off） | 让 AI 出 2-3 方案，你选一个 |
| Tasks | 任务拆解（原子级 TODO list） | 拆到每个 task 可以一轮对话完成 |
| Implementation | 代码 + 配置 | AI 写，你 review |
| Verification | 跑通 + 核心测试 | MVP 能跑 = 阶段完成 |
