## 面试官指导大纲

### 战略层：如何驾驭 AI

1. 战略上: 
    - 挖掘本质需求(第一性 ) → 明确优先级 → 定义验收标准 + 商业成功标准
2. 方案上:
    - 多方案对比 → 资源成本对比 → ROI 分析 → 用户满意度调研 → 可行性验证 → 上线后的运维监控与运营体系构建
3. 行动上: 
    - **风险**  识别 → 落地计划

### 行动层：在框架节点上

- 对 AI 的输出进行**批判**
- **补充**遗漏
- **抓关键**信息
- 提供**方案**
- 提出**创新**

## 我的策略

### 整体思路

**Spec 模式（架构师 + PM 视角）** — 不是让 AI 写完代码就完事，而是：

```
1. 需求分析（10min）：拆解场景 → 明确核心功能 → 定义验收标准
2. 方案设计（15min）：架构选型 → 技术方案 → 对比 trade-off → 选最优
3. 实现（2h）：拆 task → AI 执行 → 我 review + 纠错 + 补充
4. 验证（20min）：跑通核心流程 → 自测 → 总结产出
```

### 关键行为（得分点）

| 行为 | 对应价值观 | 示例 |
|------|-----------|------|
| 质疑 AI 输出的合理性 | 第一性 | "你这个方案的前提假设是什么？有没有更简单的路径？" |
| 指出 AI 方案的风险 | 求极致 | "这样做性能可以，但可维护性差，换个方式" |
| 补充 AI 遗漏的边界 case | 求极致 | "你没考虑并发场景 / 错误处理 / 降级方案" |
| 主动重构 AI 的代码 | 第一性 | "这段代码能工作但不够好，重构成 xxx 模式" |
| 全局视角（不只写代码） | 共成长 | "先想清楚产品目标和验收标准，再动手" |

### 禁忌

- ❌ 全程让 AI 写，自己只复制粘贴
- ❌ 不质疑 AI 输出，全盘接受
- ❌ 只关注代码实现，不考虑架构/产品/运维
- ❌ 时间管理失控，3h 结束时没有可运行的产出

## Anker 价值观映射

| 价值观 | 核心 | 在测试中的体现 |
|--------|------|--------------|
| **第一性** | 抛开表面 → 回归基础原理 → 抓住关键突破 | 不盲从 AI 建议，追问"为什么这么做"，找到最简方案 |
| **求极致** | 顶着风险 → 想尽办法 → 长期全局最优 | 不满足于"能跑"，追求代码质量/性能/可维护性 |
| **共成长** | 长期主义 + 大局为先 + 持续学习 | 展示和 AI 的高效协作模式，有复盘意识 |
