# 架构师认知体系建设

> 本质：不关心"这行代码怎么写"，关心"系统怎么组织、怎么演进、怎么不崩"。

---

## 大纲（3 条）

1. **先画骨架再填肉**：模块划分 → 接口定义 → 数据流 → 才开始实现
2. **选型有理由**：每个技术选择回答"为什么选它 / 不选别的 / trade-off 是什么"
3. **为变化留空间**：接口抽象 + 配置化 + 关注可扩展性（不是过度设计，是留口子）

---

## 速查表

| 维度 | 要问的问题 | 在飞行员测试中 |
|------|-----------|--------------|
| **模块划分** | 这个系统拆几个模块？边界在哪？ | 开局就定义目录结构 |
| **数据流** | 数据从哪来、到哪去、怎么存？ | 画清楚 input → process → output |
| **选型** | 为什么用 X 不用 Y？ | 主动告诉 AI 技术栈约束 |
| **容错** | 挂了怎么办？错误怎么处理？ | 补充 AI 遗漏的 error handling |
| **可观测** | 怎么知道它跑得好不好？ | 加日志/监控点（加分项） |
