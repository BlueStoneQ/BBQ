## 时间线大纲（120min）

### Phase 0：开局准备（0-5min）

```
① 确认提交路径+交付物（压缩包怎么交、放哪儿）
② 确认是否可重复提交（先交一版兜底）
③ /model 切 opus
④ 建文件夹结构：
   /project
   ├── docs/           ← 方案文档
   │   ├── requirements.md
   │   ├── tech-design.md
   │   ├── code-review.md
   │   └── test-report.md
   ├── frontend/       ← React + AntD
   ├── backend/        ← Node.js
   └── output/         ← 最终压缩包
⑤ 告诉 AI："所有输出存到 /project 对应路径下"
```

### Phase 1：需求拆解（5-15min）— 产品经理角色

```
Prompt：
"你是资深产品经理。我要做一个权限管理系统，需求如下：[贴题目原文]。
请帮我：
1. 拆解核心功能模块（用户管理/角色管理/权限分配/操作日志）
2. 定义每个模块的验收标准
3. 标注优先级（P0 必做 / P1 尽量做 / P2 可不做）
4. 输出到 docs/requirements.md"
```

**质疑点**："你列的功能里没有考虑 XX 场景（如：超级管理员不可删除自己），补上。"

→ 输出：`docs/requirements.md` ✅

---

### Phase 2：技术方案（15-30min）— 架构师角色

```
Prompt：
"你是技术架构师。基于 requirements.md 的需求，给出技术方案：
1. 数据库设计（SQLite 表结构：users / roles / permissions / user_roles）
2. API 设计（RESTful，列出所有接口路径 + 请求/响应格式）
3. 前端页面结构（路由 + 组件树）
4. 鉴权方案（JWT / Session）
给出 2 套方案对比，推荐一个并说明理由。输出到 docs/tech-design.md"
```

**质疑点**：
- "你的 RBAC 方案是平面的，如果有层级权限（部门嵌套）怎么办？"
- "为什么选 JWT 不选 Session？给我理由。"
- "SQLite 并发写入有限制，你怎么处理？"

→ 输出：`docs/tech-design.md` ✅

---

### Phase 2.5：任务拆解（30min）— 架构师角色

```
Prompt：
"@Arch 基于 tech-design.md，拆解开发任务到 docs/tasks.md：
- MVP：最小跑通（1 个 GET 接口 + 1 个页面渲染数据）
- V1：用户/角色 CRUD + 登录鉴权
- V2：权限分配 + 操作日志
- V3：数据看板可视化
每个版本列出具体 task、负责角色、预估耗时。"
```

→ 输出：`docs/tasks.md` ✅

---

### Phase 3：后端实现（30-55min）— 后端开发者角色

```
Prompt：
"你是 Node.js 全栈工程师。按 tech-design.md 的方案实现后端：
- 框架：Express / Koa
- 数据库：SQLite（better-sqlite3）
- 实现所有 API 接口
- 包含 JWT 鉴权中间件
- 先实现 P0 功能，代码输出到 backend/ 目录"
```

**分步执行**：
1. 先让 AI 搭骨架（入口 + 路由 + DB 初始化）
2. 再逐个模块实现（用户 CRUD → 角色 CRUD → 权限分配 → 登录/JWT）
3. 每个模块完成后让 AI 自测："运行这个接口，预期返回什么？"

**质疑点**：
- "你的密码存明文了，用 bcrypt 加密"
- "错误处理不统一，加个全局 errorHandler 中间件"

→ 输出：`backend/` 目录代码 ✅

---

### Phase 4：前端实现（55-80min）— 前端开发者角色

```
Prompt：
"你是 React + Ant Design 前端工程师。按 tech-design.md 实现前端：
- 路由：登录页 / Dashboard / 用户管理 / 角色管理 / 权限配置
- 状态管理：简单用 useState/useContext 即可
- 对接后端 API（axios）
- 输出到 frontend/ 目录
- 先实现登录 + 用户列表 + 角色分配这三个核心页面"
```

**MVP 策略**：不求完美，先跑通核心链路（登录 → 看用户列表 → 给用户分配角色）

**质疑点**：
- "Table 没有加 loading 状态"
- "角色分配用 Transfer 组件更合适，换一下"

→ 输出：`frontend/` 目录代码 ✅

---

### Phase 5：跑通验证（80-90min）

```
Prompt：
"帮我在终端里启动后端（node server.js）和前端（npm start），
确认以下链路跑通：
1. 登录获取 token
2. 用 token 请求用户列表
3. 给用户分配角色
如果有报错，修复它。"
```

→ **确保 demo 能跑** ✅

---

### Phase 6：⚡️ 兜底提交（90min）

```
⚠️ 不管做到哪里，先压缩提交一版！
"帮我把 /project 整个目录压缩为 project.zip 放到桌面"
→ 提交
```

---

### Phase 7：代码审核 + 测试文档（90-110min）— 检查者角色

```
Prompt（新窗口）：
"你是极其严格的代码审查员。阅读 backend/ 和 frontend/ 的代码，输出：
1. 安全问题（SQL 注入？XSS？）
2. 性能问题
3. 代码规范问题
4. 改进建议
输出到 docs/code-review.md"
```

```
Prompt：
"你是 QA 测试工程师。为这个权限系统写测试用例：
1. 正常流程（登录 → CRUD → 权限验证）
2. 异常流程（无权限访问 → 错误 token → 重复创建）
3. 边界条件
输出到 docs/test-report.md"
```

→ 输出：`docs/code-review.md` + `docs/test-report.md` ✅
