## Android

### 1. 签名一致性

```
坑：
├── 首次发布用签名 A
├── 更新用签名 B
└── 结果：无法覆盖安装，用户必须卸载重装

解决：
├── 一个应用终身用一个 keystore
├── keystore 丢失 = 无法更新
└── 必须备份，多份存储（KMS、加密网盘）
```

### 2. 包体积与 64 位

```
坑：
├── Google Play 2021 起强制 64 位
├── 国内商店逐步跟进
└── 只打 32 位包 = 被拒

解决：
```groovy
android {
    splits {
        abi {
            enable true
            include 'arm64-v8a', 'armeabi-v7a', 'x86_64'
        }
    }
}
```

### 3. 隐私政策与权限

```
坑：
├── 敏感权限（定位、相机、通讯录）需声明用途
├── 隐私政策 URL 必填
├── 后台定位需额外说明
└── 未声明 = 审核拒

解决：
├── AndroidManifest.xml 声明
├── 应用内隐私政策页面
└── 权限申请时弹窗说明（符合 GDPR/CCPA）
```

### 4. 内容分级

```
坑：
├── 未填写内容分级问卷
└── 应用被隐藏，无法搜索

解决：
├── Google Play Console → 内容分级
├── 如实填写（暴力、赌博、成人内容）
└── 国内商店类似
```

### 5. 国内商店差异

| 商店 | 特殊要求 |
|------|---------|
| **华为** | HMS 集成、实名认证 |
| **小米** | MIUI 适配、隐私协议弹窗 |
| **OPPO/vivo** | 应用加固、渠道包 |
| **应用宝** | 软著、ICP 备案、版号（游戏）|

## iOS

### 1. 审核被拒 Top 原因

```
1. 崩溃/闪退
   └── 必须用真机测试，模拟器不够

2. 隐藏功能/热更新
   ├── 禁止动态下发可执行代码
   ├── RN/Flutter 热更新需合规（只改配置/资源）
   └── 被发现 = 封号

3. 支付绕过
   ├── 虚拟商品必须用 Apple 内购（IAP）
   ├── 实物可用第三方支付
   └── 绕过 IAP = 拒审

4. 隐私说明不完整
   ├── 收集哪些数据
   ├── 用途说明
   └── 隐私标签（Nutrition Label）

5. 内容违规
   ├── 用户生成内容（UGC）需审核机制
   ├── 举报、拉黑、过滤
   └── 无机制 = 拒审
```

### 2. 证书与描述文件过期

```
坑：
├── 证书有效期 1 年
├── 描述文件绑定证书
└── 过期 = 无法构建/上架

解决：
├── 提前 30 天续期
├── Xcode Automatic Signing 自动管理
└── CI/CD 设置过期告警
```

### 3. 截图与元数据

```
坑：
├── 截图必须真实，不能用设计稿
├── 不同尺寸：6.7"、6.5"、5.5"、iPad
├── 文案不能误导（"最好"、"第一"需证据）
└── 未提供 = 审核延迟

解决：
├── Fastlane snapshot 自动化截图
├── 多语言本地化
└── 提前准备，不临时抱佛脚
```

### 4. TestFlight 与正式上架差异

```
坑：
├── TestFlight 通过 ≠ 正式上架通过
├── TestFlight 不审核内容，只测稳定性
└── 正式上架审核更严

解决：
├── 不要把 TestFlight 当免审通道
├── 正式上架前自查清单
└── 预留 3-5 天审核时间
```

### 5. 企业账号分发限制

```
坑：
├── Enterprise 账号禁止对外公开分发
├── 只能企业内部员工使用
└── 违规 = 账号封禁

解决：
├── 公开应用走 App Store（$99）
├── 内部工具走 Enterprise（$299）
├── 严格区分，不混用
```

## 通用坑点

| 坑 | Android | iOS |
|----|---------|-----|
| **版本号管理** | versionCode 必须递增 | version + build 必须递增 |
| **热更新合规** | 相对宽松 | 严格，需说明范围 |
| **SSL 证书** | 允许自签名（调试）| 必须有效 CA，ATS 限制 |
| **后台限制** | Doze 模式、后台启动限制 | 后台刷新严格管控 |
| **暗黑模式** | 可选适配 | 强制要求（iOS 13+）|
| **新系统适配** | Android 14 权限变化 | iOS 17 隐私弹窗 |

## "独立发布上架" 的核心能力

```
招人要求的本质：
├── 完整走过 0→1 流程
├── 踩过坑，知道怎么解决
├── 能独立处理审核被拒
├── 熟悉各商店规则差异
└── 能建立 CI/CD 自动化上架

不是：
├── 只开发过代码
├── 只调试过模拟器
└── 没碰过证书、签名、审核
```
