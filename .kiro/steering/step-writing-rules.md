# Step 文档编写规范

## 代码变更标注

每段代码块前必须标注操作类型和精确位置：

- `@add <文件路径>` — 新建文件，给出完整内容
- `@add <文件路径> — 在 <位置描述> 后插入` — 在已有文件中增加代码
- `@update <文件路径> — 替换 <位置描述>` — 修改已有文件的某段代码
- `@update <文件路径>（整个替换）` — 全量替换文件内容

示例：

```
@add app/src/main/cpp/core/src/platform_bridge.cpp（新建文件）
```

```
@update app/src/main/cpp/CMakeLists.txt — 在 add_library(...) 的源文件列表中增加一行
```

```
@update app/src/main/cpp/platform/android/jni_bridge.cpp（整个替换）
```

## 术语规范

- 使用通用技术概念，不自创术语
- PlatformBridge = 跨层通信通道（bridge 本身就是通用概念，不用再解释）
- 不用"能力合同"、"第一性"、"宿主"等自定义词汇
- 容器 > 宿主；接口 > 能力；说明/解释 > 第一性解释

## 文档结构

- 目标部分：一句话结论 + 简洁表格 + 验收标准 + 不包含范围
- 代码部分：只给必要注释，不重复解释已知概念
- 技术决策和 QA 放最后，不和实操步骤混在一起

## 注释风格

- 注释说明"为什么"，不重复"是什么"
- 对 C++ 初学者友好：关键语法（函数指针、namespace、JNI 规则）给简短解释
- 不要给每一行都加注释，只在关键决策点注释
